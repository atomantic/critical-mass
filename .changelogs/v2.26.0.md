# Release v2.26.0

Released: 2026-09-23

## Highlights

- **Accounting that holds up under partial fills.** A partly sold buy order now keeps its unsold remainder in the position. Take-profits that fill during a cancel, merge, roll-up or reconcile are booked exactly once. A sell booked in two parts counts both parts. Realized profit and reserves no longer double-count or drop fills.
- **Restarts no longer lose fills.** Partly filled entries and ladder rungs, fills missed during downtime, and tranches recorded in the ledger but never assigned to a position are recovered at startup. Anything the engine cannot prove is logged for manual review, never guessed.
- **Risk controls that actually work.** The max-drawdown limit now pauses new buys. Auto-managed sizing no longer shrinks a fund's deployment cap every cycle. A manual or external sell is no longer mistaken for a completed cycle.
- **Exchange adapters report the truth.** Crypto.com and Gemini fill scans refuse to return a partial set, EXPIRED orders are recognized, "order not found" is detected, open orders have one shape across exchanges, and Gemini's request throttle no longer trips SAFE mode.
- **Dashboard numbers agree.** The Filled Orders total now always matches the Position card's realized P&L, and Open Orders estimates use the engine's actual fee and holdback sizing. Destructive actions (cancel ladder, delete backup, reset dry-run) ask for confirmation first.
- **Safer configuration and operations.** A config save can no longer switch a fund to a different asset. Deleted Coinbase keys stay deleted. Sentinel settings are validated, and hourly snapshots include dry-run state.

## Trading accounting

- A partly sold buy order no longer drops its unsold remainder from the position. Every body sale records how much of each buy it consumed, and held cost is derived from those records.
- A take-profit that sells part of a body while being edited, reconciled, merged or repriced is booked before the order is re-placed, instead of being re-listed for the full size.
- Take-profit fills during merge and roll-up cancels are booked, and full take-profits caught by reconciliation close their cycle. A take-profit that fills while a merge is cancelling it no longer counts its holdback twice.
- A take-profit that sells more than its position holds is recorded as reserves sold, so the extra coins are no longer counted twice.
- A sell order booked in two parts now accumulates both parts' profit, cost and capital credit instead of keeping only the last.
- A manual or external sell on the product is marked as untracked and surfaced in position coverage. It no longer closes a cycle or credits the full proceeds to the deployment cap.
- DCA merge into the regime engine keeps completed trades' realized profit and starts pending buys in their own cycle. DCA consolidation handles placement errors without stranding cancelled sells.
- Filled Orders and the Position card now share one pairing rule. Legacy sells without a recorded profit may show a slightly different prorated figure.

## Restart and recovery

- Restarting while a buy was partly filled no longer strands the filled part. A restart also recovers a tranche the ledger recorded but no position absorbed, including when the position that held the order's earlier fills has already closed.
- A polled buy fill that fails processing is retried automatically, and orphaned pending entries are swept by reconciliation instead of going missing until restart.
- Known partial fills survive ladder cancels, failed catch-ups and restarts. A rung that fills while the ladder is being cancelled is counted in the right cycle and budget.
- Cycle recalculation keeps the live cycle, attributes fills missed during downtime to it, and no longer links a still-open position's buys to another position's sell.
- Ladder rebuild, ladder cancel and cycle reset no longer run on top of each other. Rebuild and cancel ask you to retry while a fill, merge or reconcile is in progress.

## Risk and sizing

- The max-drawdown limit is now enforced: new buys pause once fund equity falls past `maxDrawdownPercent`. Equity is measured so that a take-profit converting coins to cash does not count as a drawdown. A dry-run reset clears the pause, and a depleted-equity pause is shown on the dashboard.
- Auto-managed sizing uses the real exchange balance, so it no longer cuts the deployment cap by about 10% on every evaluation.
- Regime momentum thresholds are now relative to price, so non-BTC funds can enter CAUTION and TREND on momentum.

## Exchanges

- Crypto.com and Gemini fill scans reject an incomplete result instead of silently booking part of a fill as holdback. Crypto.com EXPIRED orders are recognized as finished, and "order not found" errors are detected on both exchanges.
- Open orders report remaining size, original size and price on every exchange, so Gemini's untracked-sell warning can fire.
- Time spent waiting in Gemini's request throttle is no longer counted as latency, so busy multi-position funds no longer drop into SAFE mode.

## Dashboard and API

- Cancel Ladder, Delete Backup, Reset Dry-Run and fund-state restore require confirmation. A blocked fund-state restore offers Retry or Force.
- Open Orders estimates use the engine's fee rate and exact planned holdback. Open Orders links no longer change with the Filled Orders cycle toggle.
- Capital adjust blocks a change it would otherwise silently clamp, and reports the values the server applied.
- A regime config save can no longer change a fund's traded asset. The consolidate endpoint honors the Simple DCA switch, and Sentinel settings are validated before saving.
- Manual trade import is idempotent: re-importing a buy or pair no longer creates duplicate positions or take-profits. A buy that keeps filling grows its existing position.
- Sentinel no longer re-sends alerts for items still in a feed after 7 days.
- UpDown's volume trend (OBV) signal no longer depends on unrelated older candle history.

## Operations and security

- Deleting Coinbase API keys is permanent. The legacy root `keys.json` is migrated once to `data/coinbase-keys.json` (owner-only permissions) and renamed `keys.json.migrated`.
- Hourly fund-state snapshots include dry-run state.
- Engine IPC ports outside PM2 now default to the same ports PM2 uses, so development gateways no longer dial themselves.
- Internal: config utilities, the order-executor contract and the regime dashboard are split into smaller modules, dead code is removed, and the test suite no longer collides on ports when several runs share a machine.

## Upgrade requirements

- Stop the configured Critical Mass processes before updating the deployed checkout. Then install root and admin dependencies with `npm ci`, rebuild with `npm run build`, and restart the PM2 processes. Follow the [versioned installation guide](https://github.com/atomantic/critical-mass/blob/v2.26.0/README.md) and [upgrade notes](https://github.com/atomantic/critical-mass/blob/v2.26.0/UPGRADE.md).
- **Drawdown limits now take effect.** Before restarting, check `maxDrawdownPercent` on each fund. A fund already past its limit will stop placing new buys until equity recovers or you use Resume.
- **Startup recovery may book positions.** The first start after upgrading may book previously stranded tranches into positions and place take-profits for them. Recovery books only what the ledger, the exchange order and your closed-trade history all agree on; anything ambiguous is logged for manual review. Check the engine log and the Position card after the first start.
- If a root `keys.json` exists, it is migrated and renamed `keys.json.migrated` on first start. Keep that file until you have confirmed Coinbase access.
- Rebuilding the ladder or cancelling it while a fill, merge or reconcile is in progress now asks you to retry.
- The private admin package and Umbrel packaging keep their own versions.
