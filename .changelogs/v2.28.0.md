# Release v2.28.0

Released: 2026-10-24

## Highlights

- **Size entries by long-term depression (opt-in).** Auto-aggressiveness can scale each reactive entry 0.5x–1.5x by how depressed the asset is versus its trailing year, with a capital governor that fades the boost as deployed capital nears the fund budget. Off by default. Sustained-aggressiveness advisories are also added.
- **Harder security boundaries.** The engine IPC WebSocket now requires a shared secret, operator sessions are revocable and signed with an independent per-install key, login throttling no longer penalizes successful sign-ins, and loopback alone no longer bootstraps operator enrollment.
- **Safer restarts and restores.** Configuration writes and engine restarts are serialized, placement-intent updates are serialized across processes, restores can be undone and no longer leave stopped funds or stray extracted archives, and interrupted credential writes stay out of backups.
- **More accurate accounting after restarts.** Manual or external sells are no longer booked as body profit, a partial take-profit fill is no longer booked against an arbitrary buy, fills recorded while a fund is stopped land in the active cycle, and resting entry bids are cancelled at their stale timeout.
- **Bounded, responsive APIs and dashboard.** List endpoints share one paged envelope and the admin follows every page, with request-ownership and Retry states for incomplete reads. Action results use toasts, buttons keep 44px touch targets, and narrow-screen tables, navigation and configuration controls fit small phones and tablets.
- **Resilient exchange and feed handling.** Coinbase GETs retry transient errors with fresh signatures, adapters fail closed on bad ticker prices, malformed order acknowledgements retain duplicate-placement protection, and a bad WebSocket frame or stalled handshake no longer takes down an engine.
- **Internal restructuring.** The regime engine, fill ledger and admin client are split into focused modules with shared helpers and a shared admin API client; trading behavior is unchanged by these refactors.

## Notable fixes and changes

- Timeout readout follows the resting entry's adaptive stale window; fill groups sort by recency; Regime Charts totals update from live fills.
- Backup scheduling backs off and alerts on repeated failures rather than pausing engines every five minutes; only complete fund snapshots consume retention slots.
- Sentinel keeps running and saved changes survive alert-state save failures; Telegram outages no longer delay critical alerts; news alerts no longer wait on a slow classifier.
- Engine IPC bursts fail fast with HTTP 503, slow consumers are disconnected at 8 MiB, and AI provider responses are capped at 20 MiB before parsing.
- Raw trade windows are omitted from recurring status payloads; passive trade-flow expiry is amortized.
- Dockerfile base images are pinned by digest; native upgrades document installing admin dependencies; Node 22.12 is required for runtime and admin tooling.
- Documentation clarifies holdback profit allocation, exchange ledger recovery, and zip/unzip backup prerequisites.

## Upgrade requirements

- Use Node.js 22.12 or newer. Update the checkout, run `npm ci` and `npm ci --prefix admin`, then `npm run build`. Follow [UPGRADE.md](https://github.com/atomantic/critical-mass/blob/v2.28.0/UPGRADE.md): stop the gateway first, then engines, and start engines before the gateway. Gateway and engines must be upgraded together because engine IPC now authenticates with a shared secret.
- Existing operator sessions may need to sign in again after the session-key change. Reverse-proxy installs can opt into per-client login throttling.
- Auto-aggressiveness sizing is disabled until `autoAggressivenessEnabled` is turned on.
- Check fund startup health, pending recovery actions and backup status after restart.
- The private admin package and Umbrel manifests retain their separate version histories.
