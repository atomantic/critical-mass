# Release v2.22.1

Released: 2026-07-04

## Highlights

This patch supersedes v2.22.0, which the release-automation workflow published from an early commit before the full local review pass (multiple Claude and Codex review iterations against the complete diff since v2.21.0) had finished. v2.22.0's feature set is unchanged; this release adds the real bugs that review surfaced, all with regression test coverage.

- **Order-placement reconciliation now covers the primary live trading path.** The ambiguous-placement reconciliation added for v2.22.0 (issue #226) was wired into the DCA order-manager path but not into the celestial-hierarchy executor — entry bids, take-profit placement/retry, atomic replacement, body TPs, and ladder orders now all recover correctly from a network error that may have still reached the exchange, instead of risking an untracked live order.
- **A merge-target's partially-filled TP is now booked immediately, not deferred to an event that might never arrive.** If a merge target's take-profit partially filled in the narrow window while it was being cancelled, the sold tranche's P&L/quantity deduction depended on a future fill event finding an order that had already been removed from tracking. It's now booked synchronously using data already in hand.
- **A Gemini partial IOC fill is no longer discarded.** A market buy that fills partially before its unfilled remainder is cancelled reports `CANCELLED`, but real funds moved — that fill is now recorded instead of being thrown away as an error.
- **Operator "reset cycle" action can no longer accidentally close or orphan a live position.** Resuming buying while a fund is draining could have silently closed it instead; resuming while a legacy (non-celestial) take-profit is still resting could have orphaned that live order. Both are now refused with a clear message.
- **Sentinel Telegram alerts are now fully sanitized.** An untrusted RSS feed item's title or raw description could previously break Telegram Markdown parsing or inject fake formatting; both are now sanitized alongside the AI-derived summary.
- **Optimizer results no longer let an under-covered backtest period win on totalValue alone.** A period whose backtest silently truncated to fewer candles than requested is now ranked behind every fully-covered result.
- **Unknown-outcome reconciliation retries before giving up**, tolerating brief eventual consistency on the exchange's order-history endpoint instead of risking a double-place.
- **Dashboard fetches degrade gracefully.** Several admin UI panels no longer get stuck permanently loading/disabled after a single network hiccup.

## Fixed

### Orders & reconciliation
- Wire unknown-outcome reconciliation (issue #226) into order-executor.js's entry bid, TP placement/retry, atomic replace, body TP, and ladder order-placement paths
- Retry the reconciliation lookup with backoff before declaring a placement genuinely absent
- Book a merge-target's partial-fill-during-cancel immediately via the existing fill-handling pipeline instead of depending on a future WS/poll event
- Record a Gemini partial IOC fill instead of discarding it when the order reports CANCELLED
- Surface `filledDuringCancel`'s fill details directly instead of forcing a second, redundant (and failure-prone) status fetch
- tpMutex now covers `placeBodyTpOrder`/`cancelBodyTpOrder`, preventing two concurrent live TP sells for one body

### Fibonacci strategy
- Generalize the sell-consolidation re-seed (issue #200 Bug A) so both the in-cycle and top-of-cycle fill-detection paths correctly recover a buy that outpaced a failed consolidation retry

### Operator actions
- `resetCycleBuys` refuses when the fund is draining/closed (would otherwise silently close it) or when a legacy core take-profit is still resting (would otherwise orphan it)
- `resetCycleBuys` gates on `fillInProgress`, matching `consolidateDustBodies`'s existing guard

### Security & sanitization
- `classifyByAI` uses `safeFetch` instead of a bare `fetch()`, closing an SSRF/credential-leak gap on redirect
- Sentinel Telegram alert construction sanitizes `title` and the raw-description fallback, not just the AI-derived summary
- `url-validator.js` strips brackets from IPv6-literal hostnames before validation, fixing both a false-accept (private literals) and a false-reject (public literals) bug

### Dry-run & optimizer
- Dry-run body cost basis now seeds from each body's own `avgPrice` instead of a drifting cross-body running average
- Optimizer results rank every fully-covered backtest ahead of an under-covered one before falling back to totalValue

### Admin UI
- `RegimeDashboard.jsx`, `ChartsRegime.jsx`, and `TransactionsRegime.jsx` fetches no longer leave the UI stuck loading/disabled after a network failure
