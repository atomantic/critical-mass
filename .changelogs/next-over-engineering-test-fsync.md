- **`npm test` no longer flushes disposable test fixtures to disk** — a new `tests/skip-fsync.js` preload, which the test runner loads, replaces `fs.fsyncSync` with a descriptor check. Every fixture write lands in the runner's temporary root, which is deleted after the run, so a flush protected nothing. On macOS, libuv runs each fsync as a full drive-cache flush (`F_FULLFSYNC`), and the suite issued about 16,400 of them. On a developer Mac, the full suite now takes about 30–35s instead of 115–120s. Production writes still fsync. Tests that pin fsync ordering or fsync failures replace `fs.fsyncSync` themselves and still check the same calls.
