# Release v2.25.0

Released: 2026-09-20

## Highlights

- Trading recovery detects missing exchange fills and untracked positions, keeps partially filled entries under observation, and reconciles unresolved Gemini placements automatically.
- Dry-run funds support ladder execution and retain their simulation state in the data directory across container updates and backup restores.
- Backup and migration fixes preserve fund state, transaction history, and shared candle caches while making restore compatibility and removed funds visible before applying changes.
- Engine persistence failures are reported without silent data loss; repeated save failures pause new entries while existing orders remain monitored.
- Dashboard controls have clearer labels, stronger text contrast, keyboard landmarks, and reduced-motion support; UpDown charts and shared modules load correctly again.
- Authentication, socket inputs, AI screenshot paths, request validation, and test-data isolation have stronger safeguards and regression coverage.

## Trading and recovery

- Add periodic exchange-versus-ledger drift checks and position-coverage diagnostics for adapters supporting fill reconciliation. Detection reports discrepancies without silently rewriting live accounting; the default interval is 30 minutes and setting `fillDriftSweepMs` to `0` disables it.
- Add operator tools to backfill missing fills, replace eligible synthetic fill records while preserving accounting annotations, and adopt untracked assets into the position model. Repairs default to dry-run, retain backups before applying changes, and check that the engine is stopped.
- Keep partially filled entry and ladder orders tracked until terminal, account for only their remaining pending capital, and preserve terminal cleanup on duplicate fill notifications.
- Match Gemini placement recovery by client order ID, retain precise large order IDs, and keep ambiguous or partially executed outcomes pending for reconciliation.
- Improve Coinbase fill pagination and recovered closed-trade verification, preserve operator cycle resets and unique cycle IDs across restarts, and share cycle recalculation rules between preview and apply.
- Define and validate the executor contract and add ladder placement, cancellation, and fill simulation to the dry-run executor.

## Backup, storage, and operations

- Store dry-run state per fund inside the data directory, import legacy state without altering its original file, and isolate each fund's writes.
- Keep root credential files out of backup archives, take independently scheduled fund-state recovery snapshots, bound backup schedules to safe timer delays, validate retention, and disclose destination funds removed by restore.
- Translate legacy archives into the current per-fund layout during staged restore. Restore older configuration snapshots with current defaults for newly added settings; accept snapshots from newer builds by reporting and dropping unknown fields when their revision permits it.
- Restore stranded per-fund transaction logs and shared candle caches, merge overlapping price-cache history safely, and use one cache format for backtesting tools.
- Guard engine reload and save callbacks, deliver engine fault and persistence alerts through the gateway to the UI and configured notifier, and enter SAFE mode after repeated persistence failures until saving succeeds.
- Scope Simple-DCA operations to the requested fund, persist consolidation settings, and gate legacy trade and sync endpoints on Simple-DCA being enabled.

## Dashboard and API

- Associate form controls with labels, announce switch state, add a skip link and named landmarks, improve text and button contrast, and support reduced motion and pausing the celestial visualization.
- Restore the UpDown three-column layout and browser-compatible shared modules; show an empty elapsed-time state when no entry has been recorded.
- Order Sentinel alerts by publication time, remove terminal escape sequences from streamed logs, and show restart failures when PM2 cannot manage the configured process.
- Bound asynchronous password verification and socket input processing, confine AI screenshot paths, and return structured JSON errors for malformed request bodies and query values.
- Clarify that Coinbase setup requires Coinbase Advanced API credentials.

## Upgrade requirements

- Use Node.js **20.19.0 or newer**. Stop the configured Critical Mass processes before updating the deployed checkout, install root and admin dependencies with `npm ci`, rebuild with `npm run build`, then restart the configured PM2 processes. Follow the [versioned installation guide](https://github.com/atomantic/critical-mass/blob/v2.25.0/README.md) and [upgrade notes](https://github.com/atomantic/critical-mass/blob/v2.25.0/UPGRADE.md).
- Existing dry-run state is imported automatically into each fund's data directory; retain the original root file until you have checked the migrated funds. Shared-cache and transaction-log repairs also run during startup migration.
- Drift detection does not automatically repair historical records. Review repair-tool dry-run output before applying changes and stop the affected engine first. Asset adoption uses a reported FIFO cost estimate that may span cycles; check the proposed cost and current market price because the engine may place a take-profit that executes immediately after restart.
- Review restore compatibility warnings and any destination funds scheduled for removal. Credentials remain local and must be configured separately on a restored installation.
- The private admin package and Umbrel packaging retain their independent versions.
