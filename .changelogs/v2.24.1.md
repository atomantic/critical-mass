# Release v2.24.1

Released: 2026-09-11

## Highlights

- Trading recovery preserves ambiguous order placements for reconciliation and books fills seen during take-profit cancellation before rolling positions together.
- Backup restore checks that writers have stopped, stages recoverable file replacement, and carries fund configuration across machines.
- Configuration saves reject malformed strategy values and inconsistent fund assets, preserve deleted funds, and avoid overlapping dashboard writes.
- Operator password changes require current-password proof; AI run and prompt routes reject unsafe identifiers, and Sentinel filters unsafe feed links.
- Dashboards prevent stale reads and abandoned AI runs from overwriting newer state, improve phone layouts and keyboard access, and report log-stream failures accurately.
- Transaction and scorecard views share consistent action labels, indicator weights, intervals, and numeric cycle ordering while reducing repeated calculations.

## Trading and recovery

- Preserve uncertain Coinbase, Gemini, and Crypto.com placement outcomes instead of treating them as confirmed failures; retain durable pending intents for reconciliation. Malformed lookups remain inconclusive, and adopted orders persist their position ownership before intents clear.
- Route offline fill recovery through the canonical accounting pipeline and account for execution-bearing take-profit cancellations during body roll-ups.
- Keep manual-trade imports free of partial ledger writes when validation or fill retrieval fails, and avoid placing a second recovery buy on a retry.
- Keep engine stop/start, market-data ownership, and live-order recalculation behavior covered by focused regression tests.

## Backup and configuration

- Include a versioned, non-secret effective configuration manifest in new backups and display restore compatibility before applying them.
- Drain restore writers, invalidate stale caches, and retain rollback material when file application fails. Failed recovery keeps writers blocked, and legacy data-only restores preserve the destination configuration.
- Validate nested regime settings across all save paths, reject non-boolean operation flags, and keep deleted base-config funds from returning.

## Dashboard and operations

- Keep fund Save controls visible, expose position setup before historical analysis, and improve touch targets, narrow-card layouts, and accessible dialogs.
- Show the selected asset in DCA import confirmation and distinguish scorecard prediction counts from evaluated outcomes.
- Surface failed log flushes, stop showing streaming after a log child exits, and send warnings/errors to stderr. Escape asset identifiers in Telegram daily summaries so underscore-separated pairs remain deliverable.
- Replace the third-party development process launcher with a repository-owned launcher and include archive utilities in the container image.

## Upgrade requirements

- Follow the [versioned installation and configuration guide](https://github.com/atomantic/critical-mass/blob/v2.24.1/README.md). Stop the Critical Mass processes before updating the deployed checkout, install root and admin dependencies with `npm ci`, rebuild with `npm run build`, then restart the configured PM2 processes.
- Native backup operations require `zip` and `unzip`; the container now includes both.
- Old backups without a configuration manifest require the source base configuration, or explicit data-only restore while retaining and checking the destination fund configuration. See [backup upgrade notes](https://github.com/atomantic/critical-mass/blob/v2.24.1/UPGRADE.md#backup-archives-carry-their-configuration-v2241).
- Correct malformed configuration values if stricter validation rejects a save. Browser password changes now require the current password.
- The admin package and Umbrel package retain their independent versions.
