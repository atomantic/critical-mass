# Release v2.29.0

Released: 2026-10-29

## Highlights

- **A more responsive dashboard.** Fund status, transactions, cost basis, Sentinel, UpDown and DCA views refresh from pushed changes instead of recurring polling, with refreshes on reconnection and when a tab becomes visible.
- **Safer recovery points.** Hourly fund snapshots capture unresolved placement intents, and restore preserves existing blockers. Snapshot and restore operations reject interrupted DCA imports and invalid accounting data before replacing live files.
- **More reliable trade accounting.** Coinbase fill imports reject incomplete pagination, paired manual imports avoid reusing an order already owned by another trade, and Crypto.com live fills preserve signed fees and rebates.
- **Faster large-fund views.** Transaction accounting is built on demand, cycle selection is paged and searchable, and unchanged cost-basis aggregates avoid redundant work.
- **Charts and controls stay current.** Live candles and samples survive delayed historical reads and display changes; UpDown contract drafts survive stale save readbacks; celestial previews fit the full system.
- **More dependable operations.** Health checks share bounded sweeps, gateway shutdown drains accepted background jobs, and PM2 logs are rotated to limit disk use.

## Upgrade requirements

- Use Node.js 22.12 or newer. For native installations, refresh both locked dependency sets with `npm ci` and `npm ci --prefix admin`, run `npm run build`, and follow the coordinated gateway and engine restart order in [UPGRADE.md](https://github.com/atomantic/critical-mass/blob/v2.29.0/UPGRADE.md). Check each fund's startup status after the gateway starts.
- Snapshots made before placement-intent capture require explicit acknowledgement before restore because they cannot recover unresolved order submissions. Check the exchange for open or duplicate orders before restarting the fund; existing destination intents remain protected. Snapshots made by this version capture the intents but do not determine their exchange outcome.
- Finish recovery of a pending DCA import before taking hourly snapshots or restoring an affected fund. Preserve the import journal and accounting files; do not delete the journal to bypass the refusal.
- If migration or restore finds placement-intent files at both the exchange and fund levels, it refuses to continue. With the engine stopped, preserve both copies, reconcile unresolved submissions with the exchange, and prepare one verified per-fund intent document retaining all unresolved blockers before retrying.
- Archive restore rejects symbolic links and ambiguous or unsafe member paths before extraction. Member names must be UTF-8; multi-disk archives and conflicting Unicode-path metadata are unsupported. Inspect and reconcile such archives on an isolated copy before retrying. Allow temporary space for a copy of the archive as well as the extracted files.
- DCA funds do not have a live price feed: dashboard prices update on trade or Sentinel activity and on reconnection or tab visibility, rather than on a periodic timer.
- Existing Crypto.com rows that historically recorded zero fees are not automatically corrected; reconcile historical rows if necessary. The private admin package and Umbrel manifests keep separate version histories.

## Changes

### Dashboard and charts

- Replace recurring dashboard, fund-view, Sentinel and UpDown polling with per-fund and service notifications, while refreshing on reconnect and tab visibility. The shell re-announces fund state after an engine reconnect. The AI run viewer still polls active runs.
- Refresh notification statistics after delivery, update UpDown after contract or position changes, and keep stale or switched-fund status from overwriting current prices and availability.
- Page and search transaction cycle options, compute detailed transaction rows only when needed, and scope status subscriptions to visible consumers.
- Preserve recent live chart samples and candles when historical reads arrive late or display settings change, ignore invalid live prices, and queue a trailing fills read when updates arrive during a pending request.
- Keep newer UpDown contract edits when an older server response arrives, and fit celestial previews to the whole fund hierarchy.

### Recovery and trading safety

- Capture and validate placement intents in hourly snapshots, merge them with destination intents on restore, and omit transient placement ownership locks from portable archives.
- Refuse migration or archive restore when legacy and per-fund placement-intent files coexist, so neither copy's unresolved order blockers are silently stranded.
- Reject archive path aliases and symbolic links before extraction, and keep the inspected archive generation stable during restore.
- Refuse snapshots or restores that encounter interrupted DCA imports or malformed accounting payloads. Translate legacy flat-layout archives to fund paths and refuse conflicting generations before writing.
- Reject incomplete Coinbase fill pages and paired imports that would reuse an order owned by another trade. Preserve quote-denominated Crypto.com charges, rebates and explicit zero fees.
- Bound admitted DCA work per fund and across the gateway, returning a retryable busy response when capacity is exhausted.

### Operations

- Share bounded health sweeps, drain accepted optimizer and AI jobs during gateway shutdown, rotate PM2 logs, and order backup retention by the archive's embedded creation time.
- Update operator documentation for startup readiness, recovery boundaries, simulation limits, DCA setup and selected-fund tools.
