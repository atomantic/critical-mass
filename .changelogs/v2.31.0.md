# Release v2.31.0

Released: 2026-11-21

## Highlights

- **Cross-pair arbitrage alert dashboard (monitoring only).** A new Arbitrage page watches the public Coinbase, Gemini, Crypto.com Exchange and Kraken order books for BTC priced differently across one exchange's own currency pairs. It walks real book depth with your taker fees on every leg, ranks pairs by the edge you could actually execute, and can send Telegram alerts. It never places orders and is off by default.
- **Safer fills around backups and placement recovery.** Body growth from recovered rows and the stale-order timer now wait at the backup fence instead of cancelling and re-placing orders mid-backup. Placement recovery no longer clears a stuck intent when an order filled between the open-order and fill reads.
- **UpDown paper books survive restarts correctly.** After a restart the paper books replay every buffered 1m bar, record a visible gap when bars are missing, and keep accurate totals past the 500-cycle list cap. A restore reloads them from the restored files.
- **Faster, lighter admin UI.** Global pages no longer wait on a fund. The regime dashboard paints as soon as status and config arrive and no longer redraws its tables on every price tick. Off-screen fund-card 3D scenes stop rendering.
- **Clearer fund Config page.** Advanced settings sit in collapsible cards with a "changed from default" badge, durations are entered in seconds or minutes, and the form shows the server's real defaults instead of drifted copies.
- **Releases wait for green CI.** A version is tagged only after CI passes on that exact `main` commit, and `latest` only moves forward when two releases finish out of order.
- **Large internal split, no behaviour change.** The regime engine, market data service, backup service and state tracker were split into focused modules. A backend type-check ratchet and an admin lint step now run in CI.

## Upgrade requirements

- No configuration or data migration is required. For native installations, refresh the locked dependency sets with `npm ci` and `npm ci --prefix admin`, run `npm run build`, and follow the coordinated gateway and engine restart order in [UPGRADE.md](https://github.com/atomantic/critical-mass/blob/v2.31.0/UPGRADE.md). The new dependencies are development-only (TypeScript, ESLint), and no runtime dependency changed.
- The arbitrage monitor is disabled until you enable it on the Arbitrage page. Once enabled it stores its settings under `arbitrage` in the global config and its alerts in `data/arbitrage-state.json`. Set your own taker-fee tier per venue so net edges match what you would actually pay.
- Development now pins Node 26 via `.nvmrc`. The Docker image already uses Node 26.
- The private admin package and Umbrel manifests keep their separate version histories. Umbrel is not re-pinned by this release.

## Changes

### Arbitrage monitor

- New Arbitrage page and gateway service that polls public order books on Coinbase, Gemini, Crypto.com Exchange and Kraken. It compares each BTC pair's implied price through the same exchange's FX market (for example BTC/CAD vs BTC/USD through USD/CAD), applies taker fees on every leg, and reports the largest loop size that stays profitable. Alerts open after the condition holds for consecutive polls, can optionally announce when they close, and can be sent to Telegram.
- Pairs are ranked by executable edge (selling at the bid or buying at the ask through real depth), not by mid price. This stops wide books such as Gemini BTC/EUR and BTC/GBP from looking 25–28% rich. Pairs that cannot complete a round trip on their exchange are greyed out as "no round trip".
- Watch-only alerts for pairs with no round trip open only when that pair's own book is tight (spread at most 200 bps by default). They sit in a muted section below the venues, apart from executable opportunities.
- Dismissed alerts are hidden behind a collapsed "Show N dismissed alerts" toggle.
- The venue table reads "Market buy (ask)", "Market sell (bid)", "Spread" (as a percentage) and "Size at buy / sell". The page warns when the admin UI build is older than the gateway and needs a rebuild.

### Trading and accounting safety

- `extendBody`, and the start/recalc chain that grows bodies from recovered buy rows, now park at the engine's backup fence before cancelling and re-placing a body TP. Each chain run is tracked in its own context, so a parked extend no longer stalls the backup drain for 30 s and gets the snapshot refused. A stale-entry timeout that fires during a backup waits for release and re-reads the order before cancelling. Its cancel and the known-filled-size save that protects a partial fill are no longer split across the backup window.
- An `absent` placement-evidence verdict now requires two things: fill history that reaches past the first open-order read (Crypto.com reports its scan bound), and a second open-order read, taken after the fills, that also shows no match. Any disagreement stays inconclusive for the next reconcile pass. Previously, an order that filled just before the open-order read could be missed by both reads, and its intent was released while a filled order existed.
- Stopped funds reuse a read-only parsed copy of `regime-state.json` until the file changes on disk, instead of re-parsing it every second. Operator edits still show on the next status. The cached copy never takes part in the save-conflict check that running funds rely on, and abandoned cache entries are swept.
- Coinbase backtests fetch candles through the shared Coinbase adapter and pick up its retry and timeout handling. Unused legacy Coinbase compatibility modules were removed. Live order placement and signing are unchanged.

### UpDown

- After a restart the paper books replay every buffered 1m bar, not only the last 5, so floor knock-outs, fills and expiry in the gap are priced on their own bars. If the buffer lost bars, a visible `GAP` event is recorded and a stale pending fill is dropped.
- Book totals (cycles, W/L, P&L, worst) come from running aggregates that survive the 500-cycle list cap.
- A restore stops both paper books and reloads them from the restored `up-dip-paper*.json` files. The books also stop on gateway shutdown.
- The app-history import reports `orphanedImports` (imported trades whose `importKey` no longer appears in the history). `--apply` refuses while any exist unless `--allow-orphaned-imports` is passed.

### Admin dashboard

- Overview, Backups, Notifications and Systems load immediately, without fetching a fund's summary or status or showing fund banners, tabs and lifecycle controls.
- The admin reads a fund only after the fund list confirms it exists, skips the heavy summary on regime pages other than Config, and no longer reloads the fund list after every summary refresh.
- The regime dashboard appears as soon as status and configuration arrive. Fills, chart history and presets show their own loading placeholders, and the fills table, open orders and P&L totals never show "no fills" or a partial total while fills load.
- A one-second price update refreshes only the live price, position and totals instead of redrawing the filled-orders table, open orders, configuration and charts.
- Fund-card 3D scenes stop drawing while off-screen or in a background tab, and each card loads its scene only when it scrolls into view. Visuals, the Pause motion toggle and reduced-motion behaviour are unchanged.
- The fund Config page puts Order Execution, System Health, Safety & Tail Events, Regime Detection and Macro Regime in collapsible cards. Each card shows an "N changed from default" badge, opens on its own when it holds an unsaved edit or rejected value, and remembers whether you opened it. Millisecond settings are entered as seconds or minutes and stored as before. Product ID is read-only for an existing fund.
- The Config form shows the server's own defaults for settings a fund never saved (for example k Factor 0.65, Min Interval 120000 ms, Max Cycle Buys 15, Max Open Orders 100). A setting saved as 0 displays as 0, and saving an untouched form still changes nothing.
- Clicking Restore on a backup opens "Confirm Restore" in a focused, scrollable dialog. It cannot be dismissed while a restore runs, and focus returns to the Restore button when it closes.
- Confirmation dialogs share one `ConfirmDialog` component with the same wording, focus and busy behaviour as before. Close Fund opens with focus on Cancel, and the take-profit editor opens with focus on its active input.

### Releases and CI

- A new version is tagged and published only after the CI run for that exact `main` commit succeeds. Superseded pull-request CI runs are cancelled, and push runs get a per-commit concurrency group so pending `main` runs are never dropped.
- A new version without its release notes fails the Release workflow before any tag is created. The image publish fails unless both linux/amd64 and linux/arm64 are in the pushed manifest.
- When two version bumps finish CI out of order, the older release still gets its tag, GitHub Release and versioned image, but `latest` stays on the highest version.
- Pull requests that change the Docker image inputs build the image and run the seed-config smoke test before merge.
- Release notes come from one per-PR fragment convention (`.changelogs/next-<slug>.md`), folded at release time by `scripts/fold-changelog.js`. `CHANGELOG.md` is now a short pointer, and the unused `DONE.md` archive is removed.
- Dependabot batches minor and patch updates into one PR per directory and keeps at most 3 open PRs per ecosystem. Major updates and security alerts still arrive separately.

### Developer experience

- `npm test -- tests/x.test.js` runs just that file, still isolated from the real data directory. New `test:watch`, `test:changed`, `test:admin`, `test:all` and `check` scripts cover the inner loop and the full backend, admin and build pass. The README Testing section documents them.
- The admin app is linted with ESLint and the React hooks rules (`npm run lint:admin`, also a CI step). Existing hook-dependency warnings are held under a ceiling that can only go down.
- Backend `// @ts-check` annotations are enforced in CI by `npm run typecheck`, against a baseline of existing errors that can only shrink.
- Faster test suites: the image-scan evidence and PM2 stack tests run their stubs in-process (about 1 s each, down from 13 s and 10 s), timer-bound backend tests run on the virtual clock (about 50 s less serial time), and pure-logic admin tests run in a Node environment. Real child-process coverage is kept where it matters.
- Admin accessibility and layout checks that pattern-matched source text are now render tests in `admin/tests/`. Route and deferred test helpers are shared.
- Dated audit notes moved to `docs/audits/`. Retired incident repair scripts were deleted, and a smoke test confirms every guarded script still loads.

### Internal restructuring (no behaviour change)

- The regime engine's operator actions, reconcile loop, entry evaluation and take-profit placement moved into `regime-operator-actions.js`, `regime-reconcile.js`, `regime-entry.js` and `regime-tp-placement.js`. They are code moves only: the same locks, backup fence, order of steps and P&L paths, pinned by new per-module tests plus the existing suites.
- The market data service is split into `order-mailbox.js`, `stopped-fund-order-tracker.js` and `market-data-registry.js`. Retry budgets, the start de-dup and stop-generation guard, and fill ingestion are unchanged.
- The backup service is split into `backup-archive.js`, `backup-layout-translation.js`, `fund-state-snapshots.js`, `backup-restore.js` and `backup-common.js`, and keeps its public API.
- The state-tracker facade is split into `durable-write`, `state-file-quarantine`, `placement-intent-storage`, `dca-state` and `regime-state-store`. No state file format, migration or save-version behaviour changed.
- Fund data-directory resolution moved to `src/fund-paths.js`, and the double-order guard moved to `src/placement-reconcile.js`.
- The admin shell is split into a fund controller hook, header, fund sub-nav and lifecycle dialogs, and currency helpers moved to `utils/productId.mjs`.
