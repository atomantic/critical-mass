# Release v2.30.0

Released: 2026-11-16

## Highlights

- **Backups no longer stop live funds.** Hourly fund-state snapshots and manual/scheduled backups now quiesce funds in place instead of stopping and cold-starting their engines. Websockets, market data and resting orders stay live. A fill that arrives during a backup waits at the engine's backup fence and is booked once afterwards, instead of stalling the backup for 30 seconds and causing it to be refused.
- **Coinbase placement recovery no longer blocks a fund for days.** When an order POST returned an error, automatic recovery could stay inconclusive indefinitely on a busy fund. The client-order-id lookup is now limited to orders created near the dispatch time. A failed lookup falls back to open-order and fill evidence, and Coinbase's final fills page is no longer read as truncated. An intent is cleared only when the evidence is complete and accounts for exchange rounding.
- **UpDown Up Dip Setup (paper only).** `/updown` shows a new Up Dip Setup panel with ENTER / ADD / EXIT / HOLD / STAND_ASIDE recommendations. The gateway keeps a simulated paper book on completed Coinbase 1m bars and refreshes the panel from realtime events. A second "shadow" paper book applies a daily-trend filter: it stands aside while BTC is more than 4% below its 50-day average. A fee-aware contract backtest and research scripts document the setup. Out of sample, no tested rule showed a robust edge. No order code path is involved.
- **Crypto.com app history import for UpDown.** An idempotent importer (dry run by default) adds Crypto.com app order history to the UpDown trade log and reconciles it with existing manual trades. Trade History gains a fills view, and imported amounts are locked against edits.
- **Image vulnerability scanning.** A scheduled Image Security workflow scans both Dockerfile stages, the digest-pinned Umbrel image and the storage smoke-test helper images on amd64 and arm64. Each target ends as scanned or unavailable with a reason. A verifier rejects stale or mismatched scan evidence.
- **Quieter logs.** Drawdown-pause and asset-cap entry blocks are logged once per episode, not on every price tick.
- **Dependencies and image.** Alpine zlib ≥ 1.4-r0 (CVE-2026-4738) is required in both container stages, and PM2 log rotation is 3.0.1. Also updated: Vite 8.3.8, @vitejs/plugin-react 6.3.0, jsdom 31.0.1 and vitest 5.1.0 (admin, dev), plus refreshed Node 26.13.0 / Alpine 3.24.4 base image digest and compatible transitive locks.

## Upgrade requirements

- No configuration or data migration is required. For native installations, refresh the locked dependency sets with `npm ci` and `npm ci --prefix admin`, run `npm run build`, and follow the coordinated gateway and engine restart order in [UPGRADE.md](https://github.com/atomantic/critical-mass/blob/v2.30.0/UPGRADE.md).
- Native `npm run pm2:start` now installs `pm2-logrotate@3.0.1` when no module is present, and replaces a broken 3.0.0 install with it. An existing 2.7.0 install is reused; to move to 3.0.1, run `pm2 install pm2-logrotate@3.0.1`.
- The UpDown paper trackers create `data/updown/up-dip-paper.json` and `data/updown/up-dip-paper-shadow.json`. `UPDOWN_SHADOW_MAX_BELOW_SMA_PCT` optionally overrides the shadow book's 4% threshold. The shadow book blocks entries until 50 completed daily candles are available.
- The app-history importer runs only when invoked: `node scripts/import-updown-app-history.js [--file data/updown/import/order-history.jsonl]`. It writes nothing without `--apply`. With `--apply` it backs up the ledger first, and it refuses while the gateway is online unless `--ledger` points elsewhere.
- The private admin package and Umbrel manifests keep their separate version histories. Umbrel is not re-pinned by this release.

## Changes

### Backups and accounting safety

- Funds quiesce in place for backups. A per-engine backup fence parks new accounting writers: fills (WS, poll, dry-run), reactive and ladder entries, merges and dust consolidation, ladder sweeps, reconcile ticks, safe mode, flash cancel and the metrics pass. Parked pending writes are excluded from the drain, and state saves from outside the fence are deferred until release. Parked writers run once, in arrival order, on resume. Standalone market-data services still stop and restart around the copy.

### Order placement recovery

- A failed client-order-id placement lookup is routed through the open-orders/fills evidence search. A unique match is adopted, no match clears the intent, and anything ambiguous keeps it.
- Coinbase client-order-id lookups are scoped to orders created within 30 minutes of dispatch.
- Coinbase open-order listings follow pagination and are marked incomplete when truncated or malformed. Coinbase fill history treats an explicit empty cursor as the final page, and a page without a fills array as incomplete. Gemini's trade scan treats a non-array or unfinished window as incomplete. Incomplete evidence never counts as absence.
- Evidence matching accepts both the requested size/price and the values floored to product increments.
- An order seen live on the book is not released on a possibly stale terminal-unfilled status read. Live state and the fill ledger are saved before an intent is released.

### UpDown

- `decideUpDip` setup with contract choice and expected P&L after fees. The backtest uses the app's contract formula, floor/ceiling knock-outs and Saturday expiry, and parameters are selected on Feb–Apr data only (`docs/updown-up-dip-setup.md`).
- Gateway paper tracker (`GET /api/updown/up-dip`, `updown:up-dip` realtime event) and the Up Dip Setup panel, plus a shadow paper book with the daily-trend stand-aside filter.
- Crypto.com app order history importer with contract range/expiry, fills, TP orders, exit type, fees and import keys on trade records. Trade History adds a fills view.
- The app-history importer rejects a sell that does not close exactly the contracts bought since the previous sell. The live-file guard compares resolved paths. Trade-log P&L is kept at cents, so editing an imported trade does not change its stored P&L. `UPDOWN_SHADOW_MAX_BELOW_SMA_PCT=0` is honoured.
- Research tooling (`scripts/research-up-selection.js`, `scripts/backtest-up-dip.js`, `scripts/fetch-updown-candles.js`). The shipped rule is unchanged because no filter held up out of sample.

### Operations and dashboard

- Entry-block warnings are logged once per blocking reason kind per episode.
- The Sentinel alert banner's body padding is applied in a layout effect, so the fixed banner never briefly covers the page.
- New Image Security workflow, scanner installer with pinned versions and hashes, and an evidence verifier that also requires complete artifact records and a passing, fresh scanner-control run (`docs/IMAGE_SECURITY.md`).
- Dependency and base-image refreshes listed in the highlights.
