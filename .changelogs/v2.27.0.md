# Release v2.27.0

Released: 2026-10-18

## Highlights

- **Recover uncertain orders without placing duplicates.** Accepted buys, interrupted imports and failed DCA covering sells retain durable recovery state and expose retry or replacement actions in the dashboard.
- **Keep fill accounting consistent across partial executions.** Synthetic coverage reconciliation, buy and sell corrections, cycle pairing and fee rebates preserve each execution's economics and ownership.
- **Back up and restore a quiet, durable snapshot.** Writer drains, maintenance fences and publication flushes prevent incomplete snapshots from replacing recoverable state.
- **Spot UpDown flush reversals and record actual entry times.** Dip-buy setup signals and operator-supplied buy times improve trade review; expired contracts no longer suppress every signal.
- **Use a more accessible, responsive dashboard.** Chart text alternatives, keyboard controls, larger touch targets and narrow-screen fixes make fund and trade details easier to inspect.
- **Load large histories with less repeated work.** Transactions use bounded pages, cumulative P&L follows cycle pairing, and high-rate market trades use an incremental window.
- **Upgrade the rendering and deployment stack.** React 19, compatible chart and 3D renderers, Tailwind 4, ordered PM2 lifecycle commands and immutable container publication support the updated UI and runtime.

## Order execution and accounting

- Reconcile lost or server-error placement responses by durable client order ID before allowing a replacement. Preserve partially booked buys and retry unfinished accounting without double-booking a body.
- Recover manual buy imports after interrupted saves, validate order side and product, deduplicate exchange executions, and track merge-survivor ownership.
- Expose failed Simple DCA sell placements and blocked accepted-buy recovery. Cancelled manual recovery buys can retry or link a verified replacement for the uncovered remainder.
- Serialize DCA status and explicit order reconciliation with sell retries, preventing an older snapshot from erasing a newly placed covering sell.
- Keep replacement recovery orders on the fund's exact exchange market, preserving USD/USDC distinctions where they are separate markets.
- Preserve reported executions during synthetic coverage replacement, reconcile corrected quote and fee amounts across accounting stores, and keep cycle totals consistent with body-paired profit and retained reserves.
- Book valid sell executions together with terminal fallback coverage, so already-sold asset is not offered in another take-profit order. Live economic corrections no longer block subsequent fills because of runtime signal-listener state.
- Respect entry-admission fences during stop, drain and flash cancellation. Keep late-placement cancellation sweeps supervised after bounded waits.
- Consolidate economic-dust positions that cannot clear the configured profit floor.

## State safety and lifecycle

- Drain accepted engine and gateway work before shutdown, backup or restore; transfer fill-ledger ownership exclusively between fund engines and standalone market services.
- Keep recovery fences and journals after failed saves or durability checks. Publish and flush backup archives before pruning older recovery points.
- Keep supported legacy backup archives visible for inspection and restore, while requiring valid manifests for newly published archives.
- Resume paused funds under automatic supervision after transient backup restart failures and report unfinished startup through gateway health.
- Make legacy namespace migration, transaction-log migration, DCA conversion and FIFO repair recoverable. Reject invalid fills before modifying a live ledger and quarantine unreadable state.
- Bound queued exchange order updates with coalescing mailboxes and share WebSocket lifecycle ownership.

## Dashboard and UpDown

- Add chart text alternatives and bounded cumulative P&L rendering with point selection. Keep order disclosures, trade actions, help controls and fund cards usable with a keyboard and on narrow screens.
- Keep the regime Charts page stable through its initial loading transition, and preserve fully rebated fees in Transactions totals.
- Preserve configuration and AI-provider drafts through saves and navigation; reconnect active AI runs after returning to the page.
- Show stale cost-basis data and actionable retry states instead of silently losing the last successful snapshot.
- Add the UpDown flush-reversal setup, actual buy-time price lookup and expired-contract handling. Historical scorecard publication preserves existing records and requires explicit apply mode.
- Migrate the admin app to React 19, Recharts 3 and compatible 3D libraries, and complete the Tailwind 4 migration. Add rendered dashboard-panel regression coverage.

## Security, operations and tooling

- Require matching browser origins for local operator bootstrap, reject browser-origin engine IPC connections, and revoke active sockets when the operator password changes.
- Validate every outbound DNS candidate and enforce AI endpoint-origin grants for screenshot and Sentinel requests, including redirects. Keep sensitive JSON contents out of diagnostics.
- Load native environment settings before configuration, stop the gateway before exchange engines, and wait for owned development/test subprocess cleanup.
- Publish versioned multi-platform release images from immutable tags, include safe seed configuration, and validate Docker storage ownership before bootstrap.
- Add isolated browser and route-load audit tooling, broaden lifecycle and financial regression coverage, and update dependencies.
- Isolate engine-test persistence from checkout data and correct duplicated entries in historical release notes.

## Upgrade requirements

- Use Node.js 20.19.0 or newer. Native PM2 startup requires PM2 and `lsof` on PATH.
- Stop and confirm the gateway is stopped before stopping the configured exchange engines and development UI. Update the checkout, run `npm ci` and `npm ci --prefix admin`, then `npm run build`. Start engines first, confirm initialization, then start the gateway and optional development UI. Follow [UPGRADE.md](https://github.com/atomantic/critical-mass/blob/v2.27.0/UPGRADE.md) for the exact sequence; avoid whole-daemon restarts.
- Review `AI_ALLOWED_ENDPOINTS` for every AI API origin used by screenshot analysis or Sentinel. Local bootstrap must originate from the gateway or approved development origin; remote enrollment uses the documented one-time credential.
- Rootful Linux Compose installs must prepare writable data/log bind mounts with the documented storage helper. Existing operator configuration and credentials remain in persistent storage.
- Check fund startup health, pending recovery actions, cycle totals and backup status after restart. Preserve unresolved recovery journals and follow their recovery procedure.
- The private admin package and Umbrel manifests retain their separate version histories. Umbrel continues to select its independently verified, digest-pinned release image.
